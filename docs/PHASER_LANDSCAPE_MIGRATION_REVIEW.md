# Independent second-pass review — Phaser + landscape migration plan

**Date:** 2026-09-16. **Reviewed:** the first plan draft on `docs/phaser-landscape-migration-plan` and the current `main` source, Phaser spike PR #31, pinned kit bootstrap. This is a deliberately adversarial **second analysis pass**, not an external engineer's review and not a verification of implementation. Findings below are addressed in the revised plan unless marked open.

## Decision

The spike justifies **starting a gated migration**, not an unconditional engine swap. The portfolio-wide value of one Phaser/Yandex pipeline is a legitimate requirement even though Phaser alone does not improve the skwish feel. The cheapest reliable path is: lock parity → extract simulation with old renderer still working → bootstrap a landscape candidate → migrate a complete decorated toy → unify input/platform/events → test real device/DRAFT → cut over reversibly. Do not start a broad new UI/asset redesign or blindly merge the experimental PR.

## Findings (reviewed against code / exact limits)

| Severity | Finding | Required correction / gate |
| --- | --- | --- |
| P1 | `AGENTS.md` and `docs/PROJECT_DECISIONS.md` currently prohibit/discourage Phaser. A branch implementing M2 would violate its own active instructions. | Add a **scoped migration exception and new landscape goal** before gameplay changes in the migration branch; retain production safety contracts. Update final source-of-truth after cutover. No silent contradiction. |
| P1 | First plan draft's Paint sentence contradicted `SandboxApp.handlePointerDown/Move`: a stroke may start outside the silhouette and begin when the pointer enters it. | Specify **outside→inside Paint must paint on entry**, not reject the full gesture; never paint outside boundary. Squeeze still requires valid object hit on down. Add crossing-boundary tests. |
| P1 | The green phone spike was 390×844 portrait **with Playwright mouse**. It did not test the newly required landscape layout or touch hardware. | Add landscape browser touch-emulation and actual phone/browser/WebView tests early; keep portrait as a rotation-gate recovery test. Do not call the spike mobile acceptance. |
| P1 | `PhaserSquishExtern` directly binds the default framebuffer/viewport. A simple Phaser Text-after-Extern test does not prove cameras, masks, multi-scene compositing, context loss/restore or textures. | Limit required composition modes explicitly; test foreground and background UI plus GL state on multiple stages, resize, context restoration and teardown before committing to the rendering approach. |
| P1 | Spike's `context` cast is an implementation seam, not a stable public Phaser WebGL2 config contract. Phaser.AUTO may silently Canvas-fallback where the squishy cannot render. | Enforce/verify WebGL2 support, isolate any unavoidable adapter with pinned-version tests, provide a usable unsupported message. No silent blank toy. |
| P1 | The spike's `pagehide` listener uses `{ once: true }` while skipping `event.persisted`: a bfcache pagehide may consume its only teardown listener. | Do not copy it. Use idempotent non-once lifecycle, test persisted pagehide/pageshow and later real navigation; guard async ready/storage/texture completions after destroy. |
| P1 | Bootstrap cannot simply replace the existing platform/storage: V3 decoder and rewarded shelf behavior are game-owned; a second runtime or altered key could lose progress or double rewards. The V3 loader currently falls back to defaults when current data cannot be decoded. | Reuse one existing runtime/repository. Freeze actual V3 fixtures and old-build read compatibility; test save errors, corrupted read **without overwriting the original**, reward callback retries, local/cloud path and once-only grant. Preserve exact IDs/capacity. |
| P1 | Candidate DRAFT acceptance could be postponed until after main merge, but main can auto-deploy Pages. | Build and upload a **branch/commit-addressed candidate ZIP to hosted Yandex DRAFT before default entrypoint switch**. Evidence must identify candidate hash. Public cutover only after device + DRAFT acceptance. |
| P1 | `releaseSession.ts` derives milestones from DOM mutations, so a new scene presenter could change ad timing or duplicate analytics without compile failures. | Replace observer with typed domain events only after recording existing event and eligibility traces. Test action counts, natural breaks, failed/duplicate saves and exact once-only reward, real pause/resume. |
| P1 | “Replace accessory/pearl overlays where feasible” allows permanent two-frame-loop debt while claiming complete engine migration. | Define end-state: one Phaser animation loop for *visible* toy/attached decoration, offscreen 2D baking allowed. Any remaining visible DOM overlay must be named, justified, tested and accepted explicitly; no accidental second GPU renderer. |
| P2 | “Full Phaser migration” is ambiguous if DOM Library/HUD remains. Forcing Phaser buttons may create scope creep and reduce accessibility without making Yandex integration more unified. | Define exact claim: **Phaser-owned game lifecycle/render/input + shared bootstrap**, with a documented DOM UI presenter allowed. Decide UI ownership before the stage refactor; full Phaser-drawn UI is a separate product decision unless essential. |
| P2 | Landscape reflow could become an unbounded visual redesign or inherit a fixed 2:1 canvas that clips the existing studio controls. | Require a short-height/notch/safe-area layout proof and UX acceptance before porting all screens; use kit viewport *mechanisms* rather than another game's layout constants. Keep UI pack out of critical path. |
| P2 | Phaser's extra bundle size plus the full game might breach the current 5 MiB Yandex cap. The spike ~1.4 MB chunk is not the release budget. | Inspect actual dual candidate builds and **uncompressed upload root**, not just gzip; optimize/split before any proposal to revise the budget, and measure startup on hosted DRAFT. |
| P2 | Initial 14–25 person-day range risks false precision with untouched decoration, landscape UX and hosted testing. | Treat it as a loose engineering scope envelope, re-estimate after a full decorated save and real-device layout proof; do not promise dates. |
