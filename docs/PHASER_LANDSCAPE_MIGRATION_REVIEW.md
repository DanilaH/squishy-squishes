# Independent second-pass review — Phaser migration preserving current layout

**Date:** 2026-09-16. **Scope:** source inspection and independent critical re-review of the *revised engine-first* plan, working `main`, feasibility spike PR #31 and pinned kit. This is a second analytical pass, **not external-engineer review or implementation QA**. The earlier landscape-first proposal has been superseded by the user's explicit decision to preserve the current game until the engine migration is complete.

## Verdict on sequencing

A gated Phaser migration is technically justified by the working `Extern` spike, but the prototype does **not** establish complete feature parity. Preserving current portrait-first DOM/CSS and the existing two visible 2D decor overlays materially reduces risk: do **not** migrate the UI into Phaser or force landscape just because the template happens to do so. The new order is baseline → old renderer with extracted simulation → separate same-layout Phaser candidate → full original renderer/appearance → stage input/decoration parity → existing Yandex/save/ad contracts → device/DRAFT acceptance → reversible cutover. Landscape is a **separate later project**.

## What is now explicitly OUT of engine-migration acceptance

No landscape-only redesign, no mandatory portrait rotation gate, no enforced 2:1 stage, no new style/UI pack, no move of every DOM control into Phaser, no rewrites of save/ad policies, and no new content or physical response tuning. Existing responsive landscape rendering still must **not regress**. Later landscape project should independently decide shortest supported height, safe areas, controls, orientation gate and UI layout after the Phaser game is accepted.

## Remaining open evidence

This review has **not** tested a real phone/WebView, WebGL2 device coverage, hosted Yandex DRAFT, cloud conflict semantics, all-shape/material/decor GL parity, bundle size, actual frame latency or complete cutover. They are required acceptance gates in the revised plan. No tests were run for this documentation-only change.
