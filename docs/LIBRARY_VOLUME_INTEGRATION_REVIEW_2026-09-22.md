## Actual interactive craft/Squeeze volume — separate Pages-only integration

**Scope and ownership:** `/review/pr-59/` opts the existing `PhaserSquishSurface` into `PhaserSquishCandidate(..., pagesVolume=true)`; the normal candidate and production/Yandex paths keep the default `false`. `PhaserDeformableVolume` recomputes a shallow, continuous boundary strip from the **same live `SquishSimulation.projectUvToLocal`** in Phaser's existing WebGL2 context and frame loop. It does not render a static Library thumbnail per frame, allocate a second visible canvas, start another RAF, duplicate simulation state, alter hit testing, or touch the save codec. The strip starts only after the mold and fill have completed, so early craft transitions stay intact. Squeeze deforms the actual front and side together.

The Pages-only front fragment variant derives from the existing Studio GLSL: it softens the dark edge and adds modest smooth radial cap lighting. The side fragment samples the same current appearance texture and material colours; it is darker than the front but not a fixed brown/green cutout. Shared original `src/squish/shaders.ts`, core physics, input, original `/` and `/phaser/` behavior, and Yandex output are unchanged. Sidewall buffers and shader are disposed with the Phaser scene, and lost-context cleanup drops them for lazy recreation.

**Independent visual corrections:** The first live-browser pass had an overly dark lower band and a bright dotted line at the front/side transition. Reducing thickness and lightening the side improved the band. Moving the side's inner vertices up by 0.025 local units alone did **not** remove the bright line (the sampled centre-bottom pixel stayed unchanged). The actual cause was compositing order: rendering the side behind the antialiased front left a partially blended bright edge. Drawing the same dynamically deforming side **after** the front covers that fringe; the representative paw's centre-bottom transition became continuous in actual Chromium screenshots. Do not mistake the unused vertex-offset experiment for the fix, or generalize this visual result to all GPUs.

**Reproducible browser evidence:** [first interactive volume + three saved V3 toys](https://github.com/DanilaH/squishy-squishes/actions/runs/35774978109), [softened thickness and front overlap](https://github.com/DanilaH/squishy-squishes/actions/runs/35775382784), [draw-order correction with screenshot artifact](https://github.com/DanilaH/squishy-squishes/actions/runs/35776645212).
